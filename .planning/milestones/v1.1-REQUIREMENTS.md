# Requirements: v1.1 Real LLM Integration

**Defined:** 2026-10-05  
**Milestone:** v1.1 — Real LLM Integration  
**Depends on:** v1.0 Reference Platform (satisfied — shipped 2026-05-20)  
**Status:** Planning

## Goal

Replace the WireMock LLM stub with a real OpenAI or Anthropic provider behind a feature flag, and embed a LangGraph agent loop as a Temporal activity — demonstrating that the existing observability stack captures real LLM latency, token counts, and retry behavior without changing the Kotlin/JVM 21 architecture.

## Success Criteria

1. `LLM_PROVIDER=real` env flag routes all three AI workflows (RagQa, AgentTools, BatchEval) through a live OpenAI or Anthropic API call.
2. `LLM_PROVIDER=stub` (default) continues to pass all existing smoke tests without a live key.
3. LLM call spans carry model name, token counts, and HTTP status as OTel attributes in Grafana Tempo.
4. A LangGraph agent loop executes as a Temporal activity; each agent iteration is a child span.
5. The Grafana "LLM Proxy" dashboard panels render non-stub data when run with a real key.
6. All new requirements verified by a `v1.1-VERIFICATION.md` with real-key smoke output captured.

## Requirements

### Real LLM Provider Integration (AI-01)

| ID | Requirement |
|----|-------------|
| **LLM-01** | A `LlmClient` interface (or equivalent abstraction) exists in `:workflows` or `:worker`; both the WireMock stub and the real HTTP provider implement it. Switching is controlled by an environment variable `LLM_PROVIDER` (values: `stub`, `openai`, `anthropic`). |
| **LLM-02** | When `LLM_PROVIDER=openai`, the worker sends requests to `https://api.openai.com/v1/chat/completions` using the existing OkHttp client; the `OPENAI_API_KEY` env var is the only secret required and is gitignored. |
| **LLM-03** | When `LLM_PROVIDER=anthropic`, the worker sends requests to `https://api.anthropic.com/v1/messages` using the same OkHttp client; `ANTHROPIC_API_KEY` is the only additional secret. |
| **LLM-04** | OTel spans for real LLM calls include attributes: `llm.provider`, `llm.model`, `llm.input_tokens`, `llm.output_tokens`, and `http.status_code`. The existing `OTEL-04` W3C trace propagation requirement is preserved. |
| **LLM-05** | `./scripts/smoke.sh` continues to exit 0 in stub mode with no live keys (`LLM_PROVIDER` defaults to `stub`). A separate `./scripts/llm-smoke.sh` verifies real-provider round-trip when a key is present. |

### LangGraph Activity Embedding (AI-02)

| ID | Requirement |
|----|-------------|
| **LG-01** | A new `LangGraphAgentActivity` is registered on the `ai-workflows` task queue. It accepts a prompt and a tool list, runs a LangGraph-style plan→tool→observe loop (minimum 2 iterations for demo), and returns the final answer. The loop runs inside the Temporal activity; the workflow itself remains a thin orchestrator. |
| **LG-02** | Each iteration of the agent loop emits a child OTel span named `langgraph.iteration` with attributes `iteration`, `tool_called`, and `observation_length`. The parent span is the `LangGraphAgentActivity` activity span created by the existing Temporal OTel interceptor. |
| **LG-03** | The existing `AgentToolsWorkflow` is updated (or a new `LangGraphWorkflow` added) to invoke `LangGraphAgentActivity`; the starter CLI can trigger it with `--workflow langgraph`. |

## Out of Scope

| Feature | Reason |
|---------|--------|
| Kubernetes / Helm deployment | Deferred to v1.2 (K8S-01, K8S-02) |
| Temporal mTLS | Deferred to v1.2 (K8S-02) |
| Streaming LLM responses | Adds OkHttp complexity; not needed for observability demo |
| Fine-tuned or custom models | Not observability focus |
| Multi-provider routing / load balancing | Portfolio scope |
| Changing from JVM 21 / Kotlin / Compose stack | Architectural constraint |
