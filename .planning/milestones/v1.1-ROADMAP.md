# Roadmap: v1.1 Real LLM Integration

**Defined:** 2026-10-05  
**Depends on:** v1.0 Reference Platform (shipped 2026-05-20)

## Overview

Wire a real OpenAI/Anthropic provider behind the existing activity interfaces, then embed a LangGraph agent loop as a Temporal activity. Three phases: provider swap (pure code change), LangGraph activity (new activity + workflow update), end-to-end verification with real keys.

## Phases

| # | Phase | Goal | Requirements |
|---|-------|------|-------------|
| 1 | [Real LLM Wiring](#phase-1-real-llm-wiring) | Feature-flagged provider behind existing stub interface | LLM-01, LLM-02, LLM-03, LLM-04 |
| 2 | [LangGraph Activity](#phase-2-langgraph-activity) | LangGraph agent loop as Temporal activity with child spans | LG-01, LG-02, LG-03 |
| 3 | [End-to-End Verification](#phase-3-end-to-end-verification) | Real-key smoke, dashboard validation, VERIFICATION.md | LLM-05 |

## Phase 1: Real LLM Wiring

**Goal:** Any of the three existing AI workflows can call a live OpenAI or Anthropic endpoint by setting `LLM_PROVIDER`; stub mode is default and requires no key change.

**Depends on:** v1.0 (existing `LlmActivity` HTTP client in `:worker`, OkHttp OTel propagation)

**Deliverables:**

1. `LlmClient` interface extracted in `:worker` or `:workflows` with `complete(prompt: String): String` signature (or equivalent).
2. `StubLlmClient` — wraps existing WireMock URL; used when `LLM_PROVIDER=stub` (default).
3. `OpenAiLlmClient` — calls `https://api.openai.com/v1/chat/completions`; reads `OPENAI_API_KEY` from env.
4. `AnthropicLlmClient` — calls `https://api.anthropic.com/v1/messages`; reads `ANTHROPIC_API_KEY` from env.
5. OTel span attributes added on real provider call: `llm.provider`, `llm.model`, `llm.input_tokens`, `llm.output_tokens`, `http.status_code`.
6. `LLM_PROVIDER` wiring in worker startup / activity bean construction; no workflow code changed.
7. Existing smoke tests pass unchanged with stub mode.

**Success criteria:**

1. `./scripts/smoke.sh` exits 0 with no env changes (stub default).
2. Worker log shows `llm.provider=openai` (or `anthropic`) span attribute when started with a real key.
3. Prometheus `activity.duration` histogram still populates for real-provider runs.

## Phase 2: LangGraph Activity

**Goal:** A `LangGraphAgentActivity` runs a plan→tool→observe loop inside a single Temporal activity; each iteration produces a child OTel span.

**Depends on:** Phase 1 (real `LlmClient` available for plan/synthesize steps)

**Deliverables:**

1. `LangGraphAgentActivity` Temporal activity interface in `:workflows`.
2. Implementation in `:worker`: runs 2+ plan→tool→observe iterations, calls `LlmClient` for plan and synthesis steps.
3. Each iteration wrapped in a child span `langgraph.iteration` with attributes `iteration`, `tool_called`, `observation_length`.
4. `AgentToolsWorkflow` updated (or `LangGraphWorkflow` added) to call `LangGraphAgentActivity`.
5. Starter CLI `--workflow langgraph` argument triggers the new workflow.
6. Grafana "LLM Proxy" dashboard panel updated to include `langgraph` activity type filter.

**Success criteria:**

1. Temporal UI shows `LangGraphAgentActivity` in workflow history with at least one completed run.
2. Jaeger / Grafana Tempo shows parent `LangGraphAgentActivity` span with ≥2 `langgraph.iteration` child spans.
3. `./scripts/smoke.sh` still exits 0 (stub mode, LangGraph does not require real key for loop structure).

## Phase 3: End-to-End Verification

**Goal:** Capture evidence that the full stack — real LLM calls, LangGraph spans, dashboards — works with a live key; document in `v1.1-VERIFICATION.md`.

**Depends on:** Phase 2

**Deliverables:**

1. `./scripts/llm-smoke.sh` — exercises all three AI workflows + LangGraph workflow against real provider; asserts HTTP 200, non-empty response.
2. `docs/phases/v1.1-VERIFICATION.md` — records smoke run output, Grafana screenshot paths, token count attributes visible in Tempo.
3. `docs/OPERATIONS.md` updated with a "LLM provider swap" runbook entry (how to switch `LLM_PROVIDER`, what to watch in Grafana).
4. `README.md` demo section updated with `LLM_PROVIDER=openai` example.

**Success criteria:**

1. `./scripts/llm-smoke.sh` exits 0 against OpenAI (or Anthropic) with key set.
2. `./scripts/smoke.sh` still exits 0 with no keys (stub default — regression gate).
3. Grafana "LLM Proxy" dashboard shows real latency and token count panels populated.
4. `v1.1-VERIFICATION.md` committed with captured evidence.
